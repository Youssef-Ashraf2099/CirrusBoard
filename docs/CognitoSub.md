# What `cognitoSub` Actually Is

`cognitoSub` is the permanent unique identity ID generated by AWS Cognito for every user.

Think of it as:

```text id="qymifd"
AWS Identity Primary Key
```

Example:

```text id="vf0sfd"
3f234af2-8d11-4b9d-a123-98ab12cd45ef
```

Every Cognito user gets one.

It never changes.

---

# Why Does It Exist?

Because:

- emails can change
- usernames can change
- display names can change

AWS needs a stable identifier internally.

So Cognito creates:

```text id="yjlwmk"
sub = immutable user identity
```

---

# Where Does It Come From?

When a user logs in through Cognito, the JWT token contains:

```json id="l2uq0p"
{
  "sub": "3f234af2-8d11-4b9d-a123-98ab12cd45ef",
  "email": "sara@company.com",
  "cognito:groups": ["EMPLOYEE"]
}
```

That `sub` field is the `cognitoSub`.

---

# Why Is This Useful?

Because your application needs a stable link between:

```text id="w8n41c"
AWS Cognito Identity
        ↔
Your Internal User Record
```

---

# Real Example

# User Registers

Cognito creates:

```json id="td3nnx"
{
  "sub": "abc-123",
  "email": "sara@company.com"
}
```

---

# Your Backend Creates Internal User

```json id="wqk7yx"
{
  "PK": "USER#u_1001",
  "cognitoSub": "abc-123",
  "role": "EMPLOYEE",
  "primaryTeamId": "TEAM#frontend"
}
```

Now your backend can always identify the same user.

---

# The BIG Benefit

Without `cognitoSub`, you would identify users using:

```text id="jlwm64"
email
```

This becomes dangerous.

Why?

Because users can change email.

Example:

Before:

```text id="p4x6ut"
sara@company.com
```

After:

```text id="bh3mq7"
sara.ahmed@company.com
```

Now:

- tasks break
- assignments break
- RBAC breaks
- references break

But:

```text id="n9zz7u"
sub = abc-123
```

never changes.

So all references remain valid.

# How You Use It in NestJS

# Step 1 — User Logs In

Frontend receives JWT.

---

# Step 2 — Backend Validates JWT

Using Cognito public keys.

---

# Step 3 — Extract `sub`

Example:

```ts id="3g5kxr"
const cognitoSub = payload.sub;
```

---

# Step 4 — Find Internal User

```ts id="9xol1d"
const user = await usersRepository.findByCognitoSub(cognitoSub);
```

---

# Step 5 — Load RBAC Data

Now you know:

- role
- teamId
- permissions

from your DB.

---

# Why This Architecture Is Good

Because responsibilities are separated correctly.

# Cognito Handles

- identity
- passwords
- authentication
- token generation

# Your Backend Handles

- business logic
- tasks
- teams
- permissions
- RBAC
- dashboards
